# نظام إدارة مخزون المصنع — دليل التشغيل والنشر

تطبيق ويب كامل لإدارة مخزون مصنع الملابس، يشتغل من المتصفح على أي جهاز (كمبيوتر أو موبايل)،
بتسجيل دخول مستقل لكل عامل، وتنبيهات تلقائية عند وصول أي صنف لأقل من 15% من حده الأقصى،
وتقارير كاملة قابلة للطباعة (PDF) والتصدير كملف Excel.

هتحتاج تعمل حسابين مجانيين فقط، وكل الخطوات تحتها بالتفصيل:
- **Supabase** (قاعدة البيانات + تسجيل الدخول) — مجاني
- **Netlify** أو **Vercel** (استضافة الموقع) — مجاني

---

## الخطوة 1: إنشاء قاعدة البيانات على Supabase

1. روح إلى [supabase.com](https://supabase.com) واعمل حساب مجاني (بإيميلك أو بحساب Google).
2. اضغط **New Project**، اختار اسم للمشروع (مثلاً `workshop-inventory`) وكلمة مرور لقاعدة البيانات (احفظها في مكان آمن)، واختار أقرب منطقة (Region) لك.
3. لما المشروع يخلص إنشاء (بياخد دقيقة أو اتنين)، روح لـ **SQL Editor** من القائمة الجانبية.
4. اضغط **New query**، افتح ملف `schema.sql` المرفق هنا، انسخ كل محتواه، والصقه في المحرر.
5. اضغط **Run**. هيتنشئ كل الجداول والحماية والبيانات التجريبية تلقائيًا.
6. روح لـ **Authentication > Providers**، وتأكد إن **Email** مفعّل. بعدين روح لـ **Authentication > Settings** وأطفي خاصية **Confirm email** (عشان الحسابات تشتغل فورًا من غير ما تحتاج تأكيد بالإيميل، لأننا مش هنستخدم إيميلات حقيقية).

### الحصول على مفاتيح الاتصال
من القائمة الجانبية: **Project Settings > API**، هتلاقي:
- **Project URL**
- **anon public key**

افتح ملف `config.js` والصق القيمتين بدل:
```js
const SUPABASE_URL = "PASTE_YOUR_SUPABASE_URL_HERE";
const SUPABASE_ANON_KEY = "PASTE_YOUR_SUPABASE_ANON_KEY_HERE";
```

## الخطوة 2: إضافة حسابات العمال (اسم مستخدم + كلمة مرور)

كل عامل هياخد اسم مستخدم بسيط (زي `ahmed`) بدل إيميل كامل. من **Authentication > Users** في Supabase:

1. اضغط **Add user > Create new user**.
2. في خانة الإيميل اكتب: `ahmed@warsha.local` (يعني اسم المستخدم + `@warsha.local` بالظبط زي ما هو مكتوب في `config.js` في `USERNAME_SUFFIX`).
3. حط كلمة مرور له.
4. فعّل **Auto Confirm User** لو ظهرت الخيار.
5. كرر نفس الخطوات لكل عامل (`sara@warsha.local`، `mohamed@warsha.local`... إلخ).

العامل بعد كده هيدخل التطبيق بكتابة `ahmed` في خانة اسم المستخدم، وكلمة المرور اللي انت حطيتها له — بدون ما يحتاج يعرف الإيميل الكامل.

> لو عايز تغيّر اللاحقة `@warsha.local` لحاجة تانية، غيّرها في `config.js` *قبل* ما تنشئ أي حساب، ومتغيّرهاش بعد كده عشان الحسابات القديمة متتعطلش.

## الخطوة 3: رفع الموقع على استضافة مجانية

### الطريقة الأسهل — Netlify (بدون أوامر برمجية)
1. روح إلى [app.netlify.com/drop](https://app.netlify.com/drop)
2. اعمل حساب مجاني لو لسه معملتوش.
3. اسحب مجلد `workshop-inventory` كامل (بعد ما تكون عدّلت `config.js`) وأفلته في الصفحة.
4. هيديك رابط جاهز خلال ثواني (مثلاً `https://your-app-name.netlify.app`) — ده الرابط اللي هتشاركه مع العمال.
5. تقدر تغيّر اسم الرابط من **Site settings > Change site name**.

### أو عن طريق Vercel
1. روح إلى [vercel.com](https://vercel.com) واعمل حساب مجاني.
2. اضغط **Add New > Project > Deploy** وارفع نفس المجلد (أو اربطه بحساب GitHub لو رفعت المشروع هناك).
3. هيديك رابط جاهز بنفس الطريقة.

بعد الرفع، جرّب تفتح الرابط وسجّل دخول بأي حساب عامل عملته في الخطوة 2.

## استخدام النظام

- **إدخال مخزون / سحب من المخزن**: العامل بيدور على الصنف، يحدد الكمية، ويأكد — بدون أي تعقيد.
- **تنبيه أقل من النسبة المحددة**: شريط أحمر أعلى الشاشة يظهر تلقائيًا لأي صنف وصل للحد الحرج (15% افتراضيًا، وقابل للتغيير من الإعدادات).
- **الإعدادات والأصناف**: من هنا تضيف اسم المصنع، الشعار، العنوان والهاتف، أنواع المنتجات (الفئات)، وتضيف/تعدّل/تحذف الأصناف يدويًا (بكود وباركود تلقائي).
- **إدارة المستخدمين** (للمدير فقط): تحديد دور كل مستخدم (مدير / أمين مخزن / قراءة فقط) وإيقاف أو تفعيل أي حساب.
- **سجل العمليات (Audit Log)**: كل عملية إدخال أو سحب أو تعديل أو تسجيل دخول مسجّلة بمن قام بها، وقتها، الجهاز، والكمية قبل وبعد.
- **البحث السريع**: بالاسم أو بكود الصنف (مثال: FAB-0001)، متاح في شاشات الإدخال/السحب/المخزون.
- **التقارير**:
  - تقرير الأصناف المنخفضة والحرجة
  - الأصناف الأكثر سحبًا
  - ملخص يومي (عدد وكمية عمليات الإدخال والسحب لكل يوم)
  - سجل كامل لكل حركة بالتاريخ **والساعة**
  - زر **طباعة / PDF**: يفتح نافذة طباعة المتصفح — اختار "حفظ كـ PDF" كوجهة الطباعة للحصول على ملف PDF
  - زر **تصدير Excel**: يحمّل ملف `.xlsx` فيه كل التقارير في شيتات منفصلة

## تحديث مشروع موجود بالفعل (المرحلة الأولى الجديدة)

لو عندك مشروع شغّال بالفعل على Supabase، شغّل ملف `migration_phase1.sql` (مش `schema.sql`) من **SQL Editor** — آمن تمامًا ولن يفقدك أي بيانات موجودة.

**خطوة إجبارية بعد التشغيل**: أول حساب هيتسجل هيبقى دوره الافتراضي "أمين مخزن". لازم ترقّي حسابك الشخصي لـ"مدير النظام" يدويًا بتشغيل الأمر ده في SQL Editor (بعد تغيير الإيميل لإيميلك):

```sql
update public.profiles set role = 'admin'
where id = (select id from auth.users where email = 'admin@warsha.local');
```

بعد كده هتلاقي تبويب "إدارة المستخدمين" ظاهر، وتقدر تتحكم في باقي الحسابات منه.

> لمشروع جديد من الصفر: شغّل `schema.sql` الأول، وبعده `migration_phase1.sql` بنفس الترتيب.

## الأمان (المرحلة الخامسة)

- **تسجيل خروج تلقائي**: أي مستخدم بيتسجل خروجه تلقائيًا بعد 20 دقيقة من عدم النشاط (عدم لمس الماوس أو الكيبورد أو الشاشة).
- **تغيير كلمة المرور**: زرار 🔑 بجانب "خروج" في القائمة الجانبية، يقدر أي مستخدم يغيّر كلمة مروره بنفسه في أي وقت.
- **استعادة كلمة مرور منسية**: بما إننا مش بنستخدم بريد إلكتروني حقيقي (الحسابات بصيغة `username@warsha.local`)، إرسال رابط استعادة تلقائي بالإيميل مش متاح. البديل: المدير يقدر يعمل "Reset Password" لأي مستخدم مباشرة من **Supabase → Authentication → Users → اختر المستخدم → Reset Password**، ويديله كلمة مرور مؤقتة جديدة.
- **منع تسجيل الدخول المتكرر**: بعد 5 محاولات فاشلة بنفس اسم المستخدم، يتم إيقاف تسجيل الدخول لمدة 5 دقائق تلقائيًا.
- **سجل آخر تسجيل دخول**: يظهر لكل مستخدم في تبويب "إدارة المستخدمين" (وقت آخر دخول + نوع الجهاز).

## إنشاء وحذف المستخدمين من داخل التطبيق (يحتاج خطوة نشر إضافية)

عشان زرار "مستخدم جديد" وزرار الحذف النهائي في تبويب "إدارة المستخدمين" يشتغلوا، لازم تنشر Edge Function صغيرة على Supabase (مرة واحدة بس). ده مطلوب تقنيًا لأن إنشاء/حذف حسابات دخول عملية حساسة، ولازم تتم بمفتاح خاص (service role) ميظهرش أبدًا في المتصفح.

**الخطوات (مرة واحدة فقط):**

1. ثبّت Supabase CLI على جهازك:
   ```
   npm install -g supabase
   ```
2. سجّل دخولك:
   ```
   supabase login
   ```
3. من داخل مجلد المشروع (اللي فيه مجلد `supabase/`)، اربطه بمشروعك (الكود ده تلاقيه في رابط مشروعك على Supabase تحت Settings > General):
   ```
   supabase link --project-ref your-project-ref
   ```
4. انشر الدالة:
   ```
   supabase functions deploy manage-users
   ```

خلاص، مفيش خطوات تانية — مفتاح الـ service role بيبقى متاح تلقائيًا جوه بيئة الدالة من غير ما تحطه إنت يدويًا في أي مكان.

**قبل النشر**: زرار "مستخدم جديد" والحذف النهائي هيديك رسالة خطأ توضح إن الدالة لسه مش منشورة — باقي كل حاجة تانية في التطبيق شغالة عادي.

## ملاحظات مهمة

- البيانات كلها مشتركة بين كل العمال المسجّلين — أي عامل يقدر يشوف ويعدّل نفس المخزون، مفيش أمين مخزن منفصل.
- الخطط المجانية من Supabase وNetlify/Vercel كافية جدًا لمصنع صغير أو متوسط (آلاف الأصناف والحركات شهريًا بدون أي تكلفة).
- لو عدد العمال أو الحركات زاد جدًا مستقبلًا، ممكن تحتاج ترقية خطة Supabase المدفوعة، لكن ده مش متوقع في الاستخدام العادي لمصنع.
- احتفظ بنسخة من `config.js` بعد ما تعدله، ولا تشارك مفتاح الـ **service_role** (لو شفته في Supabase) مع حد — إحنا بنستخدم مفتاح **anon** بس وهو آمن للاستخدام في الموقع.
